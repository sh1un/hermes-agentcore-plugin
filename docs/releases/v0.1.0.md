# v0.1.0: Per-user AgentCore MVP

First versioned MVP release of the Hermes AgentCore Plugin.
The plugin runs inside Hermes and provides per-user AgentCore integration.

## Included

- Native Slack App Home Google/Cognito login with PKCE and explicit account confirmation
- Direct browser login buttons, callback-driven Home refresh and visible connect/confirm/sign-out actions
- Consent Portal entry for managing delegated third-party connections
- Per-requester read-only Jira dispatch through AgentCore Gateway
- Immutable request identity snapshots, bounded concurrency and stale-result rejection
- Safe Gateway diagnostics and MCP SDK v2 wire-format compatibility fixes
- OAuth URLs, confirmation codes and credentials kept out of model-facing authorization interfaces
- Hermes runtime image built by GitHub Actions and published to GHCR

## Pin this release

Plugin source: checkout Git tag `v0.1.0` rather than a moving branch.

Runtime image: `ghcr.io/sh1un/hermes-agentcore-plugin:v0.1.0`.
Use the image digest recorded in the GitHub Release for immutable deployment pins.
The bundled plugin must also be enabled in Hermes configuration, as described in
the installation documentation. Source checkout alone does not configure AWS or Slack.

## MVP boundaries

- Cognito login state is in memory. Restart or expiration requires sign-in again
- Local sign-out is not revocation of the provider's OAuth grant
- Already admitted upstream requests cannot be cancelled by local sign-out
- Generic MCP dispatch and channel-bound service-account routing are not included
- AgentCore department policies and autonomous alert triage are follow-up work
- Automated tests and image publication do not prove live Jira success, cross-user
  isolation across all host memory paths, or production compatibility
- No claim of process-level credential isolation from arbitrary code execution

No new service-account feature or cloud deployment is part of this release.
